# 精度：原理、誤差來源與模擬

## 時間域

- **local**：每顆晶片自己的 `esp_timer`（µs），由模組上的 40 MHz 晶振驅動。RMT 也用同一顆晶振，所以修正 local 的 ppm 就等於修正 LTC 輸出速度。
- **net**：共同的參考時鐘。
  - hotspot 模式：手機熱點的 TSF（beacon 內 8-byte 時間戳，由手機 Wi-Fi 硬體在發送當下填入）。
  - espnow 模式：master 的 `esp_timer`。

所有 node 都只對 net 對齊，參考時鐘本身準不準不影響 node 彼此之間的同步。

## 對時流程（`SyncClock`）

1. **對時視窗**：無線電開啟，收集 `(local 收到時間, net 時間)` 成對樣本，10 Hz。
2. **第一個視窗（≥ 8 s）**：穩健線性迴歸（3×MAD 剔除離群值）求出初始 ppm。
3. **每個視窗**：用目前的 ppm，取樣本中位數求出視窗中點的偏移 → 一個錨點。
4. **錨點之間**：`ppm = (Δnet / Δlocal − 1)`。間隔 10 分鐘、錨點誤差 20 µs 時，ppm 誤差約 0.03 ppm。
5. **溫度模型**：每段錨點間隔的平均溫度與 ppm 一起存進 `TempRateModel`；溫度範圍 ≥ 2 °C 時擬合直線，≥ 8 °C 時擬合拋物線；否則只更新偏移量、保留原本的斜率。
6. **自己跑**：每 5 秒讀一次溫度，在當下重新定錨並改用該溫度的 ppm，相位保持連續。
7. 偏差 > 50 ms（熱點重開、換 master）視為跳變：重新建立錨點，下一個視窗重新量 ppm。

## 輸出（`Engine` + `PhaseController`）

- RMT 一次排 5 幀。每幀結束時由 ISR 打時間戳，換算到 net 後和理想的幀起點比較。
- 控制器先把「已排入但還沒播完的修正量」加進誤差（Smith predictor），再做 PI 修正；每幀長度最多改 ±2 %。
- 誤差超過半幀時直接改幀號（啟動、換參考），剩下的再慢慢修。
- 分數 tick 會跨幀累加，長時間沒有捨入誤差。

## 誤差預算

| 來源 | 大小（估計） | 怎麼處理 |
|---|---|---|
| 收 beacon 的軟體時間戳抖動 | 數十～數百 µs，偶爾數 ms | 中位數、MAD 剔除、長基準線 |
| beacon 長度不同造成的收完時間差 | 數 µs～數十 µs（看 beacon 長度與速率） | 同一支手機對所有 node 相同，互相抵銷 |
| RMT 交易之間的重啟空檔 | 約 10 µs | PI 積分項吸收 |
| 晶振出廠誤差 | ±10–40 ppm | 校正掉 |
| 晶振溫度係數 | 每 °C 約 0.1–0.5 ppm（依切角） | 定期對時 或 溫度模型 |
| 晶振老化 | 每年約 1–3 ppm | 每天開機重新校正偏移量 |
| 板子/接法不同的常數延遲 | 數 µs～數十 µs | `output_offset_us` |

## 24 小時模擬（`test/test_sim.cpp`）

**假設（不是量測值）：**

- node 晶振：`ppm(T) = 17 − 0.15 (T−25) + 1.1e-4 (T−25)³`（類 AT-cut 曲線）
- 晶振溫度以 5 分鐘時間常數跟隨環境；環境溫度 20 → 30 → 20 °C，再加 ±1 °C 的小波動
- 溫度感測器：比晶振高 3 °C 的固定偏差（已校正）、0.3 °C 雜訊、0.25 °C 解析度
- 信標：每 100 ms；發送端 CSMA 延遲 0–500 µs；發送 / 接收 callback 延遲為指數分布（平均 40 / 50 µs），另有 3 % 機率多 1–5 ms；掉包 5 %
- RMT：交易間空檔 8–12 µs，ISR 時間戳抖動 0–6 µs

（這是 espnow 模式的較差情況；hotspot 模式的時間戳由硬體填入，發送端抖動不存在。）

**結果：**

| 情境 | 24 h 內最大 \|誤差\| |
|---|---|
| A：每 10 分鐘對時、溫度補償、溫差 10 °C | 0.14 ms |
| B1：只校正一次、無溫度補償、溫差 10 °C | 60.3 ms |
| B2：只校正一次、溫度補償（使用 A 學到的曲線） | 3.9 ms |
| B3：只校正一次、無溫度補償、恆溫 25 °C | 0.3 ms |

一天 15 ms 相當於 0.17 ppm，屬於 TCXO 等級。模擬顯示「定期對時」或「事先學好的溫度曲線」都能做到，但模擬沒有包含：

- 手機 SoftAP 實際的 TSF 行為
- 溫度感測器的非線性與自身發熱（對時視窗期間不採溫度）
- 晶振溫度遲滯、供電電壓變化
- 真實的 promiscuous 模式接收延遲分布

所以請用 [verify.md](verify.md) 的方法實測你的組合。
